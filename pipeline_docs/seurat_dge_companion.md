# seurat_dge Companion Guide

This document explains what the `seurat_dge` helper does in general and how it is used in this repository.

## File and Scope

- Helper implementation: `primary_dependents/seurat_dge_local.R`
- Primary entry function: `seurat_dge(...)`
- Scope in this repo: used for differential expression in scripts 9 and 11.

## What seurat_dge Does (Overall)

`seurat_dge` is a wrapper that standardizes differential expression workflows on Seurat objects.

At a high level, it:

1. Validates requested subsets (condition, cluster, category).
2. Subsets cells based on the provided metadata columns.
3. Runs one of three DGE modes:
   - `mast`
   - `wilcox`
   - `pseudobulk`
4. Returns structured results indexed by condition and tested cluster/group.

## Main Inputs

Key arguments used to control behavior:

- `seurat_object`: Seurat object with count data and metadata.
- `dge_method`: one of `mast`, `wilcox`, or `pseudobulk`.
- `cluster_column`: metadata column used for cluster identity.
- `category_column`: metadata column used for group comparison.
- `test_categories`: two labels to compare (order matters).
- `test_clusters`: cluster(s) to test, or `all`.
- `test_condition` and `condition_column`: optional condition-level subsetting.
- `freq_expressed`: minimum fraction of cells expressing a gene for inclusion.
- `filter_genes`: `inner` or `outer` logic for gene filtering across the two groups.
- `gene_set_blacklist`: optional vector of genes removed before testing.

## Method-Specific Behavior

### MAST mode

When `dge_method = "mast"`, the function:

- Filters genes by expression prevalence in each tested group.
- Applies optional blacklist filtering.
- Constructs `Group1` and `Group2` labels from `test_categories`.
- Fits MAST models and returns:
  - raw results
  - filtered results
  - model objects and metadata needed for downstream use

This is the mode used by the manuscript pipeline in this repo.

### Wilcoxon mode

When `dge_method = "wilcox"`, it performs Seurat/FindMarkers style rank-based DE using the same grouping conventions.

### Pseudobulk mode

When `dge_method = "pseudobulk"`, it:

- Exports temporary count and metadata files.
- Calls a Python pseudobulk helper shipped with the `seutools` package.
- Runs DESeq2-based testing on pseudobulk profiles.

Note: this path depends on `seutools` package internals and its Python helper layout.

## Output Structure

`seurat_dge` returns a nested list keyed first by condition, then by tested cluster/group.

Typical access pattern in this repo:

- `obj[["media"]][["target_cluster"]][["raw_res"]]`

Columns commonly used downstream include:

- `primerid`
- `logFC`
- `fdr`
- `pvalue`

## How This Repo Uses seurat_dge

## Scripts that source the helper

- `primary_script/9[FigA]_umaps_mast.R`
- `primary_script/11_test_mast_real_vs_sim.R`

## Script 9 usage

Script 9 uses `seurat_dge` in MAST mode for three analysis blocks:

1. Study-day contrasts within each of `MPA`, `cMono`, and `nMono` (`SD1` vs `SD3`).
2. Platelet versus cMono contrast to build a platelet-gene blacklist.
3. MPA versus cMono contrasts at SD1 and SD3, with blacklist filtering applied.

Representative settings in script 9:

- `dge_method = "mast"`
- `pseudobulk_test_mode = "cluster_by_category"`
- `filter_genes = "outer"`
- `freq_expressed = 0.1`
- `fc_threshold = log2(1.25)`

Script 9 writes DGE outputs into `intermediate/mast/...` for downstream scripts.

## Script 11 usage

Script 11 uses `seurat_dge` in MAST mode for observed-vs-sim MPA comparison.

Key details:

- Compares `droplet_type` categories `MPA_sim` vs `MPA_real`.
- Normalizes sim naming compatibility before testing (`SimMPA` is mapped to `MPA_sim`).
- Applies the platelet-gene blacklist generated by script 9.
- Writes output to `intermediate/mast/mpa_real_sim/...`.

## What seurat_dge Is Not Used For in This Repo

- Script 10 (Figure B dotplot) does not call `seurat_dge`.
- Script 13 GSEA uses its own standalone `fgsea` workflow and does not call `seurat_dge`.
- The legacy `seu_mast_gsea` helper was removed from `seurat_dge_local.R` as unused by this repo pipeline.

## Practical Notes for Future Edits

- Keep metadata naming stable (`cell_type`, `study_day`, `study_id`, `droplet_type`) because grouping logic depends on exact column names passed to function arguments.
- Preserve comparison order in `test_categories`; direction of logFC depends on this order.
- If adding pseudobulk usage later, verify `seutools` and its Python helper paths are available in the runtime environment.
